# Repository architecture and validation

Verified against the working tree on 2026-11-15. Paths are repository-relative. Recheck manifests/source before changing contracts or dependencies.

## Boundaries and sources

| Area           | Implementation and starting points                                                                                                                                                                                                                                                                                                                       |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Workspace      | pnpm workspaces in `pnpm-workspace.yaml`; scripts/tool versions in root and app `package.json`. Packages retain `@nexus/api` and `@nexus/web`.                                                                                                                                                                                                           |
| Web            | Next.js 16 App Router, React 19, TypeScript, Tailwind v4, Radix/shadcn. `apps/web/src/app` defines routes; `src/features` owns business screens/API/model/hooks. `src/components/layout`, `src/components/ui`, and `src/lib` supply shared pieces.                                                                                                       |
| API            | Express 5, Prisma 7, PostgreSQL/Supabase. `apps/api/src/app.ts` mounts routers and HTTP protections; `src/index.ts` starts the server; `src/lib/db.ts` supplies Prisma. Controllers often mount routes directly, with feature-prefixed schema/service/repository files; some features retain `routes.ts`, `validation.ts`, or `service.ts` entry points. |
| Data           | `apps/api/prisma/schema.prisma` and migrations define accounts, workforce, catalog/requests, conversations, workflow/payments, projects/deliverables, workload, attendance, and scoped management history. `ExampleItem` remains a starter model, not a domain pattern.                                                                                  |
| HTTP           | Web port 5173; API 3001. `apps/web/next.config.ts` rewrites `/api/*` using server-only `API_PROXY_TARGET` (default `http://localhost:3001`) and builds standalone output. `src/lib/api-url.ts` still supports `NEXT_PUBLIC_API_URL`; preserve the mandated same-origin default rather than introducing direct-origin calls.                              |
| Authentication | API `features/auth/auth.jwt.ts`, `auth.middleware.ts`, `auth.service.ts`, and session/repository code; web `features/auth/api/auth-api.ts`. JWT access tokens last at most 15 minutes, with refresh tokens and database-backed sessions. Middleware resolves current account state. Scrypt hashing lives in `auth.password.ts`.                          |
| Authorization  | API `features/auth/auth.permissions.ts` and `auth.capabilities.ts`; web `features/auth/model/permissions.ts`, workspace route policy, and feature-specific access checks. Administrative grants and operational scope remain independent.                                                                                                                |
| Modules        | Shared `apps/api/src/features/modules/module-registry.json`, API module controller/service, web `features/workspaces/model/module-registry.ts`, `route-policy.ts`, and `features/dashboard/model/workspace-modules.ts`. A card alone does not prove a complete module.                                                                                   |
| Mobile         | Kotlin/Compose Multiplatform Android/iOS targets; inspect `apps/mobile/shared/build.gradle.kts`, Gradle version catalog, and `shared/src`. Common `App.kt` is greeting/demo UI, not implemented business workflows. pnpm checks do not validate native/Gradle targets.                                                                                   |
| Operations     | `compose.yaml`, `compose.prod.yaml`, `Dockerfile`, and app scripts define development/standalone deployment. Database credentials and storage secret keys belong only in API environment. Migrations/seeds against configured data are not test validation.                                                                                              |

Supporting context: `docs/filestructure.md`, `docs/modularization.md`, `docs/session.md`, and relevant feature records. Verify older starter/session prose against source.

## Commands and test mechanics

| Purpose             | Command / evidence                                                                                                                                                                                                                                                                                          |
| ------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Mandatory gate      | Run `pnpm format`, then `pnpm lint`, then `pnpm typecheck`. Lint enforces zero warnings.                                                                                                                                                                                                                    |
| CI                  | `.github/workflows/ci.yml` checks formatting, lint, typecheck/build, secrets, and dependencies. It does not currently execute application test suites; run relevant tests yourself.                                                                                                                         |
| Development/build   | `pnpm dev` starts API/web; `pnpm build` builds pnpm apps, not mobile. Web prepares standalone assets; API generates Prisma and compiles TypeScript.                                                                                                                                                         |
| Prisma/typecheck    | `pnpm db:generate` after schema edits. API typecheck also generates Prisma and checks through `tests/tsconfig.json`; web runs Next type generation and TypeScript.                                                                                                                                          |
| Test orchestration  | `pnpm test` runs API, web unit, and browser via `scripts/tests/`; `pnpm test:unit` omits browsers. Individual commands: `pnpm test:api`, `pnpm test:web`, `pnpm test:e2e`.                                                                                                                                  |
| API                 | `pnpm --filter @nexus/api test`; test-path arguments select suites. `apps/api/scripts/run-tests.mjs` compiles to isolated `.test-build/run-*` output and uses native Node, recursively discovering `tests/**/*.test.ts` by default. Reuse `tests/support/pglite-app.ts`.                                    |
| Web unit            | `pnpm --filter @nexus/web test` uses Node's runner for `test/*.test.mjs`.                                                                                                                                                                                                                                   |
| Browser             | `pnpm --filter @nexus/web test:e2e`. Inspect `playwright.config.ts` and fixtures. Default builds current web output on port 5273 with server reuse disabled. Suites use mocks and real offline Express/PGlite fixtures. Environment overrides/live mode alter behavior; do not enable live mode implicitly. |
| Database operations | `pnpm db:migrate --name <name>`, `pnpm db:studio`, API `db:seed` / `db:seed:services` are available. Inspect target and task authorization before operations that mutate/expose configured database state.                                                                                                  |

Use the neighboring ci-readiness skill for troubleshooting when appropriate, but verify its command/path assumptions against current manifests/workflow. Do not propagate its legacy absolute CI link.

For the full non-live browser baseline and verified contract updates, read `docs/features/browser-regression-contract-remediation.md` and its preserved original report/per-case manifests. Internal landing expectations use `/module`, Clients retain `/dashboard`, and role-specific account menus and auth-field sizing must be checked against current components. Selected passing suites are not evidence of a clean complete browser gate. Mobile action-menu/carousel failures remain separately tracked; do not hide them with forced clicks, skips or increased timeouts.
