## Fixtures, mocks and cleanup boundaries

- API tests use startPgliteApp from apps/api/tests/support/pglite-app.ts. It starts migrated in-memory PGlite, points Prisma at the disposable database, creates local synthetic accounts/sessions, starts local Express, and registers cleanup. It does not use a live database.
- API projection tests create synthetic Staff, Heads, Admin, Superadmin, User and department/employee rows. Tests use locally issued bearer tokens. No production data or external notification is required.
- Web regression support builds role fixtures and supports restoreSession with synthetic departments. The Superadmin People & HR spec captures page errors and uses synthetic route responses. Its API interception is a mock boundary. PortalLayout separately calls GET /api/auth/me to resolve the actor, then mounts PreferencesProvider for admitted accounts, which calls GET /api/auth/settings; these shared shell requests are not assertions for department metrics. A future PG-022 browser fixture must provide synthetic account and settings responses as well as GET /api/departments.
- apps/web/playwright.config.ts uses e2e/**/*.spec.ts, Chromium and a local base URL. The default webServer builds local Next and starts a stub public-service upstream. CI retries can be 2; the future focused plan overrides to one worker and zero retries.
- The PG-021 integrated spec used its own server fixture and was executed with an isolated Next-to-Express-to-PGlite path. It bypasses neither actual Next rewrite nor API authentication for its observed membership operation.
- QA_GATE_RECOVERY_STAGE_3_REPORT.md concerns Attendance split modules, single shared hook registration, assertion preservation and an isolated fixture. PG-022 does not import or modify those modules, hooks or fixtures.
