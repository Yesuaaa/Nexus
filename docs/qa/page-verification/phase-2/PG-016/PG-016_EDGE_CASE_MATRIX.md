# PG-016 Edge Case Matrix

Zero payments, one payment and many records use both empty section messages and due/history membership. Null booking/reference/approval/submission/proof values must avoid invalid dates or empty action labels. Positive/zero and maximum decimal values are verified independently at API and rendering boundaries. Canceled pending/submitted versus verified, sandbox prefix with real/null verifier and client-hidden proof are API fixtures. Late response and late blob fulfillment are controlled by gates with cleanup in finally. Failed download, repeated click and closing dialog while pending follow current inline guards. Invalid currency or malformed untrusted response currently has no schema guard; no product fallback invented. Long names and dates, keyboard and narrow widths need browser assertions. Upload, payment submission, filtering and pagination are inapplicable to this page. Preview error presentation remains contract-blocked.
