## Environment and implementation dependencies

- Use `tests/support/pglite-app.ts` for API cases and the current attendance browser fixture for actual browser/API/PGlite paths. Do not use a developer database for default API tests.
- Reuse existing Head, HR, Superadmin, profileless ADMIN, department-transfer, policy, session, and correction factories where their state matches each isolated scenario.
- Mocked Playwright responses must match the attendance adjustment DTO, include capability booleans deliberately, and intercept same-origin `/api` calls only after restoring an account session.
- The attendance browser spec is serial and owns fixture startup/teardown. Use one worker for focused selections and avoid parallel runs against its fixed port.
- T032 needs an explicitly verified disposable PostgreSQL database, migration setup, independent connections, coordination/barrier support, and a runner path that cannot silently use a normal `DATABASE_URL`. Prior PG-008 reported a PostgreSQL environment blocker; current availability was not tested in this discovery task.
- No production-code, schema, API-contract, or permission change is proposed. Case expectations follow current source behavior and existing approved workflow rules.
