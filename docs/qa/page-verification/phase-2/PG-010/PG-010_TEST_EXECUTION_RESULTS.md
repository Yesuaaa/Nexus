## T032 environment evidence

- Both task-owned disposable PostgreSQL containers used for PG-010 were removed; pre-existing `nexus-web-1` and healthy `nexus-api-1` remained running.
- The test container used `postgres:16` and a 256 MiB tmpfs mount for `/var/lib/postgresql/data`. Before migration, the isolated database had zero public tables and no seeded users, departments, or adjustments.
- The repository migration deploy completed 91 migrations with exit 0. After the final test, the task-owned container was removed and `docker ps` showed only the two pre-existing application containers.
- No normal development database or shared persistence service was used. Temporary credentials are intentionally not recorded.

## Authoring corrections and reliability

- T002 initially expected every denied role to redirect to `/module`; source route policy sends USER to `/dashboard`. The test now asserts the source-defined per-role redirect and passed.
- T006 initially expected the UI to show Employee ID, but the table displays the employee's full name. The assertion now checks the visible full name and passed.
- The first T032 attempt exposed a harness observer filter that did not see a blocker and could wait beyond Prisma's transaction timeout. The test now observes same-database blockers without the narrow application-name filter and uses a bounded 2.5-second wait; it passed against a fresh migrated container.
- T035 was not changed to hide the failure. Its two reproduced failures are retained as a regression signal for the already open shared row-menu defect.
- Playwright generated ignored trace/error-context artifacts on failures. No generated artifact is included in the source change set.
