## 9.1 Threat model

Assets: client User identity/contact PII (name/email/phone/active status/date), credential hashes and session/refresh credentials, related request/project associations and safe metadata, account lifecycle and management-history integrity. Employee records matter only as unwanted side effects to exclude; creation does not provision Employee. No file bytes, upload, payment, approval or sensitive configuration control exists here.

Actors: anonymous; USER with own/foreign known IDs; STAFF/current Department Head; ADMIN; SUPERADMIN; inactive/retired/expired/revoked management session; recently downgraded role. Administrative cross-client/cross-department inspection is intended. Privacy means nonmanagement denial and correct parent/field projection, not invented owner-only restrictions for managers.

| Boundary                            | Untrusted input                                                             | Trusted server state / enforcement                                                                         |
| ----------------------------------- | --------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| Browser -> API                      | Path/query/body/header claims, stale browser permissions, retries           | Verified bearer/session/current User and fixed role permissions                                            |
| Frontend route/affordance -> policy | Hidden UI bypass, forged create permission                                  | Portal gate is presentation; Express independently gates every route and exact SUPERADMIN PATCH/DELETE     |
| Requested parent -> related data    | Path id, extra clientId/departmentId/role params, nonUSER/Trash IDs         | Parent role/deletion + clientId predicate in RepeatableRead; explicit safe selects                         |
| Controller -> Prisma                | Malformed bodies, unexpected fields, duplicate identity, query manipulation | Parser allowlists/normalization, parameter values/whitelisted order keys, Serializable writes              |
| Mutation -> history/session         | Forged actor/operation/time/changes, replay/fault                           | Server-created operation UUID/actor, history allowlists, same transaction, conditional archival/revocation |
| Async response -> UI selection      | Late client/tab/page result                                                 | Abort/active guard, drawer key client.id and related kind check                                            |

CORS is not authorization. Web tokens remain sessionStorage-only. Server reads current role/session, not submitted role or stale JWT role. Valid bodies are required for router-auth tests; malformed global JSON can fail before requireAuth. No instantaneous cancellation of already authorized in-flight transactions is promised.

## 9.2 Abuse inventory and traceability

Severity is potential impact **if a defense fails**, not an observed exploit. Likelihood is qualitative source/coverage evidence, not a measured probability. HIGH=significant protected PII/account/audit failure; MEDIUM=contained material workflow/query/transaction inconsistency; LOW=limited bounded misuse. No Critical rating is justified. P0 prioritizes auth/privacy/attribution; P1 material boundary correctness; P2 bounded UI/resource misuse. Existing assertions below remain unexecuted in this task.

## 9.3 Authentication and authorization

ABUSE001-004 establish valid current-session authority, current role revocation, USER/STAFF/Head denial and independent read/create grants. Production has no per-user grant editor; revocation tests change session/active/deleted/current role. The read-only catalog override is isolated test configuration. Admin may create USER but cannot PATCH/DELETE. Superadmin cannot target arbitrary non-USER accounts through Client endpoints. Frontend mocks alone never establish backend authorization.

## 9.4 Input/request manipulation

ABUSE005-008/010-013/018/020 map finite body/query/ID/rendering matrices and fixed writable fields. Supported repeated/structured query values reject400; unknown keys are ignored. Extra role/ownership fields and PATCH password are ignored safely, not universally400. Malformed id400 versus missing/nonclient/retired404 is source-defined. Name/phone/email/password constraints are separate; API password 1024 UTF8 bytes is not UImaxlength256. Literal LIKE metacharacters and harmless SQL/markup-like text suffice; no destructive execution/fuzzing or external payload is needed.

## 9.5 Business-logic abuse

ABUSE007-009/013-017/021-022 concern actual create, reserved update/archive, replay, role/hash preservation, linked-history retention, rollback and retry. There is no approval/payment/file/edit/delete UI to abuse. Same normalized-email POST replay is409, not cached201; source has no create idempotency-key contract. Pending guards do not replace server uniqueness. Stronger lost-response recovery and optimistic conflict UI are outside the defined source expectations.

## 9.6 Data integrity/concurrency

Preserve PGlite history-fault rollback and ordinary overlapping archive assertions. Independent PostgreSQL A017-T003/A020-T002 are REQUIRED for those specifically proposed contention claims: owned migrated DB, real independent backends, bounded gates/lock evidence and teardown. PGlite suffices for branch predicates/projection/validation/serial replay/session cascade/rollback; it does not prove multi-backend SSI schedules. Concurrent read/count snapshots under external writes are optional future work outside46 records. No stress or unbounded cross-feature race campaign. See [plan](PG-019_UNIT_API_E2E_PLAN.md).

## 9.7 Information disclosure

Assert exact projection keys and parent counts/rows, not only absence of a password substring. Exclude passwordHash/tokens, raw workflow/workPlan/private descriptions and nonexistent file metadata. no-store applies to API. Development explicitly has diagnostics; non-development errors must exclude SQL/stack/location/details/secret sentinels. A generic duplicate-email409 is source-defined; it must not reveal the existing account's role, Trash state or private values. Manager access to both parents is intentional, but wrong-parent association is still incorrect.

## 9.8 Availability/resource abuse

Source limits: search 100, page 100000, pageSize 10, JSON 16KiB, password 1024 bytes. A finite edge matrix verifies caps, not throughput/capacity. No dedicated Clients rate limiter was observed; this authenticated administrative surface is not an anonymous hash endpoint. No vulnerability, rate-limit status expectation or DoS finding is inferred. Load/stress testing needs separate authorization.

## 9.9 Audit/traceability

Actual contract is transaction-local AccountManagementChange with real actor/role/UUID and safe transitions/field names, no raw profile/credentials. Active identical update has no false history; inactive identical update records revocation completion without a fake status transition. Denials/duplicates/linked archives and rolled-back operations must not append successful account history. Session activity is not a business write. No universal audit-per-read/denial requirement is invented; shared incident logging remains separate.
