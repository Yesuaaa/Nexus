## Supporting fixtures and mocks

- apps/api/tests/support/pglite-app.ts starts the API with isolated in-memory PostgreSQL-compatible PGlite, applies migrations, creates auth sessions, and supplies teardown. Reuse it for focused API persistence assertions.
- apps/api/tests/support/attendance-browser-server.ts seeds employee/policy/assignment data and starts the local browser API fixture used by the Attendance Playwright suite. Reuse rather than making tests depend on a configured live database.
- attendance.spec.ts has file-local auth, clock, and API helpers plus serial state. A separate Playwright file cannot import those helpers as-is; keep integrated cases additive in that file or use existing exported/shared fixtures without copying mutable fixture state.
- attendance-policy-assignment.spec.ts owns deterministic route mocks for policy pages, employees, and assignment POSTs.
- No dedicated PostgreSQL-specific PG-008 policy-assignment concurrency test was found. Current PG-008-compatible API tests are PGlite-backed. PostgreSQL locking is a separate proposed test because lockRows and ReadCommitted semantics are database-specific.
