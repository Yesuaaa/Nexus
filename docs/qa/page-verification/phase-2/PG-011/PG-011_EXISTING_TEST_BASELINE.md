## Fixtures, mocks, execution environment and reliability

- API workflow tests use `apps/api/tests/support/pglite-app.ts` (`startPgliteApp`) and fixture-owned in-memory PostgreSQL. The parent leave test seeds Staff, Head, Admin, Superadmin, an outsider, departments, policy days/assignments, and a frozen attendance clock. It asserts persisted Prisma records and HTTP response contracts.
- The attendance browser fixture is started by `apps/api/scripts/run-tests.mjs --fixture tests/support/attendance-browser-server.ts` and listens on `127.0.0.1:5391`. `attendance.spec.ts` is configured serial, forwards same-origin browser API traffic to this isolated backend, and seeds actor tokens in `sessionStorage`. It is a real Browser → Next.js → Express → Prisma/PGlite path.
- `superadmin-attendance.spec.ts` stubs relevant `/api/leave` responses; it covers UI rendering only, not API persistence. It has environment-dependent skip behavior recorded in that spec; inspect current skip gates before selecting it in Phase 2.2.
- The opt-in PostgreSQL migration test is a separate target with explicit database and cluster checks. Its presence does not make all PG-011 concurrency behavior verified.
- Shared menu reliability: PG-004-D-001 is confirmed. PG-010 T035 reproduced the menu keyboard failure at 390, 820 and 1440 px on two runs. PG-006 T024 remains intermittent at 820 px. PG-008's existing 390 px compatibility test had a fixture failure. These findings are preserved; none is evidence that PG-011 itself has failed.
- PG-010 T032 passed a separate disposable PostgreSQL 16 concurrency case. Treat that as potential infrastructure reuse after reconfirmation. It does not resolve PG-008's separate assignment-concurrency blocker.
