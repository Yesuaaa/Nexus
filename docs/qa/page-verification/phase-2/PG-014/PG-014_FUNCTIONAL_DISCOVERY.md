## Route and authorization

The root auth provider supplies transition state. The portal loads the current bearer account before rendering, then mounts Account, Preferences, Breadcrumb and Workspace providers with the role layout and AttendanceShell. Anonymous initial entry goes to `/login`. Known-account revocation uses the role-specific login path. Denied USER goes to `/dashboard`, and denied internal accounts go to `/module`. A first-load account service error can render a portal alert. The exact overview policy uses `canManageAttendance`: active STAFF with headship or active ADMIN/SUPERADMIN with `employees:read`. No `employees:manage` or Employee link is required for privileged reads. UI navigation follows route policy. Module entry, Time Logs navigation and manager entry through `/attendance` converge here. The Time Logs group base has a policy entry but no standalone page file. Legacy records and audit redirects resolve to their respective pages. The header View records and the Records sidebar link target `/attendance/time-logs/records` without carrying filters.

The attendance router applies bearer authentication before its GET handlers. Invalid/expired/revoked sessions and inactive/deleted accounts receive 401. The management layer re-reads the actor, resolves organization scope through role-derived `employees:read`, otherwise resolves current STAFF headship through Department.headId, or returns 403. Scope is enforced independently of client state. A head gets the current department even with no requested filter. Another valid-shaped ID is rejected before existence lookup. Privileged filtered reads return 404 for a valid nonexistent department. Department listing accepts no meaningful query input and projects only id/name, ordered by name.

## Initialization, controls and display

On mount the page uses the UTC date strings from browser time minus 30 days and plus one day (`attendance.ts:103–109` in the attendance model) and the empty department ID. Department and overview reads start independently. The selector starts disabled and later exposes All permitted departments followed by server choices. Selecting or clearing a department or committing either date updates local state immediately. Date fields pass reciprocal min/max constraints and the date popover commits on calendar selection. Escape dismisses a selection in progress. No submit or confirmation is involved. The overview GET serializes from, to and departmentId, including the empty ID, and passes an AbortSignal. Rapid changes, disable and unmount clean up obsolete requests. Editing dates or department does not reload choices.

During overview loads the figures advertise busy, and the status/Coverage sections show skeletons. A completed overview shows unique employees with sessions, total sessions, closed sessions and working plus unpaid-break sessions. An open total above zero adds Needs review. Four status rows stay in a fixed order when total is positive, with independent integer percentages and named visual bars. Zero total shows the empty message even when leave or sessionless records exist. Coverage shows employees with sessions, recorded workdays, approved leave days and a one-decimal sessions-per-employee ratio, or a dash for zero employees. Overview failure shows dashes, an unavailable message and a Retry. Department failure leaves overview values available and the All option available after loading. Each alert retries only its own resource. Both dates are needed for a request. Clearing one disables the request and can expose previously settled data because the hook retains it. Its intended presentation is deferred.

## Persistence and accessibility

GET handlers delegate directly to attendance management rather than self-service controller handlers. Both reads use Prisma RepeatableRead transactions. The overview strictly accepts from/to/departmentId. Date defaults come from the injected clock if omitted, and invalid or reversed ranges, disallowed query keys, invalid IDs and ranges longer than 366 inclusive days return 400. Report SQL uses inclusive stored work dates and current Employee department on both sides of a full outer join of recorded days and positive approved leave. Session detail derives from related workday sessions and breaks. Leave-only dates are synthesized and overlapping employee dates merge onto the recorded day. The cap is 10,000 merged rows. The response also carries legacy aggregates and up to eight sorted recent activities with employee names and action IDs. The current page consumes neither those names nor audit/policy/request details. No Attendance or Leave writes occur. Session activity may be touched by auth. Department head IDs are unique. Workdays are unique by employee/date, sessions reference their workday and employee, and leave days are unique by request/date. Prisma models and relationships are anchored at `apps/api/prisma/schema.prisma:451,824,1253–1300,1502–1571`.

The sidebar and header action use links. The date inputs and Radix select have accessible names. Both calendar triggers use Open calendar, so scope each locator to its input wrapper. The date popup has a named dialog, focuses a calendar day on open and restores input focus on Escape. The select supplies combobox/options and manages keyboard/focus through Radix. Retry is a button inside an alert. The table uses native headings, and Coverage uses a definition list. The toolbar wraps and the Coverage rows stack at 560px and below. Verify actual focus, clipping and overflow during browser implementation. In-page row actions, search, sort, pagination, report export/upload, detailed record panels, bulk actions and mutation controls are inapplicable.
