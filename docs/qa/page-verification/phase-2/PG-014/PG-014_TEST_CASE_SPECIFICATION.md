# PG-014 Test Case Specification

Case IDs use the prefix `PG-014-F001-`. Source keys link to repository paths in [Functional Discovery](PG-014_FUNCTIONAL_DISCOVERY.md). Coverage IDs refer to the [Existing Test Baseline](PG-014_EXISTING_TEST_BASELINE.md). Setup and action columns specify inputs and reproducible steps. When a case uses the WC-06-F02 fixture, take the canonical work date and following date from that fixture.

**Disposition** New = NEW TEST REQUIRED. Add = ADDITIONAL ASSERTION REQUIRED. Existing = EXISTING COVERAGE SUFFICIENT. Blocked = CONTRACT CLARIFICATION REQUIRED. Unsupported controls and database writes are NOT APPLICABLE and have no executable IDs.

**Environment and dependencies** Unit uses Node and source imports with fake time/account objects. Browser uses Chromium and a real Next.js page with explicitly intercepted account and page APIs, except the current B6 compatibility case, which retains its existing mock helpers. API uses bearer actors, real Express and Prisma/PGlite on isolated loopback with a fixed attendance clock. Integration uses the B1/B3/B4 attendance fixture and its real Next document, intercepted same-origin browser requests forwarded to the fixture on port 5391, real Express/Prisma/PGlite and persisted rows. In integration A009/A010 the initial 503 is mocked and the sibling/retry are real. No integration record exercises the Next.js rewrite. Shared shell conversation/settings/notification requests can remain mocked.
