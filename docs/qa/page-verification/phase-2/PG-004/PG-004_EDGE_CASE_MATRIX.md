## Concurrency and recovery notes

- Use request/response gates, not fixed sleeps, for debounced search, stale responses, and review races.
- Keep full-stack conflict fixtures isolated in the attendance PGlite server. Revoke Head assignment or create the winning review within test-controlled steps, and always restore shared fixture state in `finally` blocks.
- Assert both visible UI state and persisted API state for review conflict cases. A toast/error alone does not prove the client cleared stale private data.
- Do not change the expected UI contract for ordinary correction conflicts to match overtime recovery; source only special-cases OVERTIME rows.
