## Test infrastructure and reliability notes

- `apps/api/tests/support/pglite-app.ts` starts a migrated in-memory PostgreSQL-compatible PGlite database and registers cleanup. API test plans must use it; no live database is needed.
- `apps/api/scripts/run-tests.mjs` sets `--test-concurrency=2`. Keep PGlite fixtures isolated and use deterministic dates/attendance clocks.
- `apps/web/e2e/attendance.spec.ts` configures serial execution and starts the isolated attendance browser API fixture. New live integration coverage belongs in that environment or a clearly equivalent isolated fixture; do not count intercepted API responses as persistence tests.
- `apps/web/e2e/async-resource.spec.ts` is intentionally skipped in live mode because it intercepts failures. Preserve the skip and do not count it as successful live execution.
- PG-006 T024 intermittently fails at 820 px within the grouped attendance matrix because the Check-Ins row-action menu item is absent; one isolated run passed and two matrix runs failed. PG-004-D-001 is the confirmed same `RowActionsMenu` defect. PG-007 itself does not render the menu, so these failures are a shared-suite execution risk, not evidence that PG-007 overview has the defect.
- Focused prior PG-006 browser tests also use the same attendance spec fixture and serial ordering. Run PG-007 focused cases independently with one worker before drawing a new overview conclusion.
