## Atomic relationship and coverage IDs

The parent mapping remains PG-002-F001; this decomposition does not create new Phase 1 IDs. The proposed test specification uses the pattern PG-002-F001-Axxx-Txxx. Existing behavior maps as follows:

- A001/A002: role and access helper tests; NEX-019 list query parameters; NEX-020 list failure/retry; Superadmin search-preview browser case.
- A003: NEX-002/NEX-021 browser creation; account-attribution PGlite creation/history/rollback; role-policy create hierarchy.
- A004: account-edit PGlite API test, role-policy/role-leadership API tests, and browser role edit/self-role denial.
- A005: account-status HTTP/mock test, account-attribution PGlite mutation/rollback tests, role-policy helper, browser status success/failure/cancel.
- A006: account-management-access unit policy, account-password PGlite API test, and responsive browser password flow.
- A007: account-status and account-attribution API coverage; browser success/cancel currently combines the soft-delete journey with Trash.
- A008: account-restore PGlite API test plus responsive browser success/failure/cancel flow.
- A009: account-status and account-attribution API coverage; browser happy path combines movement to Trash with permanent deletion.

These are source-level mappings only. See [existing test baseline](PG-002_EXISTING_TEST_BASELINE.md) for declaration counts and direct/partial distinctions.
