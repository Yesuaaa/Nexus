No additive unit case is proposed because the existing pure access/role-policy declarations already cover the relevant shared helpers; page-local search and form behavior are better exercised through the rendered UI. Existing API lifecycle suites already cover password, status, archive, restore, deletion, role policy, session revocation, history and rollback.

## Deferred contract cases

- T003 remains reserved for the list-response 401/403 destination decision. Source behavior is described, but expected role-specific destination is not agreed.
- The create form's stricter name and phone rules compared with the API/edit paths are recorded as C1 in [gaps and dependencies](PG-002_GAPS_AND_DEPENDENCIES.md). T008 avoids asserting a policy for the divergent inputs.
