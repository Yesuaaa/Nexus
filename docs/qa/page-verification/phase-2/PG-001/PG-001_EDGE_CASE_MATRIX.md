## Test boundaries

- Empty and missing values are distinct cases: the existing route test proves a no-token visit, while `T002` proves the falsy stored-string boundary.
- Session invalidity is not checked by the root. `T006` and `T009` exercise the later protected-account flow so the distinction remains explicit.
- The internal-role matrix in `T005` verifies frontend handoff destinations only. It does not establish backend RBAC or prove all protected resources deny unauthorized requests.
- No database mutation or ownership boundary is reached by the root. No production PostgreSQL, payment provider, or external service is needed.
- No source-supported defect is established by these boundaries. The whitespace token condition is an unresolved product contract, not a declared defect.
