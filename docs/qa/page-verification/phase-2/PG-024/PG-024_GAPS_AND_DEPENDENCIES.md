## Source-backed gaps and suspected issues

- **Stale role documentation:** `docs/features/employee-management.md:9` says only ADMIN has `employees:read` and that Superadmin cannot access the page/API. Current `route-policy.ts`, both permission maps, and Phase 1 authorize ADMIN and SUPERADMIN. Record the discrepancy; do not change the earlier feature report in this task.
- **Over-fetch:** the overview discards `EmployeeList.employees` and keeps `total`, but the request response still carries projected names, emails, phone numbers, account state, and HR fields. This is an observed data-flow/minimization gap for an already authorized role, not evidence of unauthorized disclosure or a confirmed security defect. C003 controls whether API contract work is expected.
- **Different count populations:** the default employee total counts undeleted ADMIN/STAFF accounts, including account-only and inactive-login rows. Department `memberCount` counts Employee relations, including rows without a User link. “Placed” can therefore describe a different population than “Employees”; source does not state these values should match. Tests should assert each source's own semantics, not equality.
- **Failure defaults:** an initial Employee batch error can display zeros with an error. The code is clear; the intended user contract is not. Do not change expected values or label a confirmed defect without a decision.
- **Department recovery affordance:** the page has no Department retry button although the hook exposes a callback. This is an observed UI capability gap; whether it violates product intent is C002.
- **Performance:** a normal page load issues a fixed nine Employee list requests and one Department request in parallel. There is no per-page latency/call budget in the source or approved PG-024 contract. Do not fabricate a threshold or uncontrolled load test. PG-023-C003 remains scoped to its own directory-volume decision.
- **Malformed successful data:** the client uses TypeScript response casts; no runtime decoder is visible in this path. PG-023-C001 remains the existing malformed-success contract. This report does not select fallback behavior or create a duplicate PG-024 contract.
- **Authorization documentation versus implementation:** API permission is independently required for each read; front-end menu visibility does not authorize data. Department GET returns a restricted field set to actors without `employees:read`; the overview route itself requires privileged Employee read.

No confirmed PG-024 application defect or vulnerability is declared. The four C records are product/design dependencies, not environment blockers.
