### Source trace and applicability

The Portal layout and exact route policy enforce overview admission. The page calls `listEmployees` and `useDepartments` through the same-origin API client. The Next rewrite forwards the two GET paths. The Employee controller authenticates, requires Employee read permission and validates filters before calling the repository. The repository scopes account roles and `accountDeletedAt`, applies Employee relationship filters and paginates with a count in the endpoint transaction. The Department controller requires Department read permission. Its service applies the projection boundary and derives `memberCount` from the Department–Employee relation. Employee linkage uses the optional unique `Employee.userId` relation in the Prisma schema. Neither read handler performs a domain write. Authentication may touch session activity.

The overview contains no multi-step mutation or approval workflow. Its directory link crosses into the separately assessed PG-023 route. Direct API authorization, malformed request handling, possible data exposure, repeated reads and interrupted reads still apply to PG-024 and are accounted for above. No entire category is marked NOT APPLICABLE.
