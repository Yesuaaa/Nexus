## Fixtures, mocks, database, and runner

- Web unit source: Node test declarations under apps/web/test; the relevant test imports the real navigation and route policy modules. No browser or database is used.
- API tests: node:test against a real Express app and apps/api/tests/support/pglite-app.ts. PGlite applies project migrations to an in-memory PostgreSQL-compatible database and provides isolated persistence. The target API tests do not require a live database.
- Browser fixture: attendance.spec.ts spawns the dedicated attendance-browser-server test process. That test process creates a PGlite app with seed users, departments, assignments, policies, and session tokens. Browser requests under /api are intercepted and forwarded to the fixture API origin; the browser does not use the production Next.js API proxy for these test requests.
- Playwright failure injection: WC-06 tests add targeted page.route handlers for delayed responses and synthetic 503 responses. The 401 test removes Authorization for a real API call; the 403 test changes department Head assignment and calls the real endpoint.
- Browser web server: apps/web/playwright.config.ts:10-38 uses base URL 127.0.0.1:5273 and, absent NEXUS_E2E_BASE_URL, starts a production web build/server. Browser tests run Chromium. The attendance spec is serial even though the overall config permits parallel files.
- PostgreSQL-specific integration: not needed for this read-only aggregate page. No concurrent writes or database locking contract is implemented by PG-013. PGlite is adequate for endpoint and persistence-read verification.
- Skips/flakiness: no skip or fixme is present in the PG-013 WC-06 declaration block. The current discovery did not execute these tests and therefore makes no pass or reliability claim. The attendance spec's serial fixture and previously documented PG-006 820 px intermittency are relevant planning context, not evidence of PG-013 intermittency.
