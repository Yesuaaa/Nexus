## Corrected first-run issues

- The first web build and web typecheck exited 1 with TS2554 at the sparse-status assertion: diagnostic text was passed to the matcher instead of Playwright's expect call. The assertion was corrected without changing its expected result. Final pnpm typecheck and browser build passed.
- The first browser run of the exact focused Playwright command exited 1: 11 passed, one failed, and three did not run. The failure showed that setting sessionStorage in an already mounted account context did not replace its in-memory Head account. The test now opens a distinct page for the second account, waits for its current data, and then releases the old response. The final focused rerun passed 15/15.
- The first Leave API invocation, using the exact command listed above, exited 1 with 28 passing declarations and a failure reported both at the nested scenario and enclosing suite. The chosen “outsider” fixture had been made a Head by an earlier test in the same file. The new non-Head case now uses the existing ordinary Staff actor with no Head relationship. The final PGlite rerun passed 30/30.
- The initial un-escalated web unit command exited 1 because pnpm could not acquire its shared store lock. Running node --test directly exited 1 because the sandbox denied the test worker spawn. The same focused pnpm unit command with required process/store access passed 9/9.
- These were test implementation, fixture, or execution-environment corrections. No initial run established an application defect, and no expected application result was weakened.
