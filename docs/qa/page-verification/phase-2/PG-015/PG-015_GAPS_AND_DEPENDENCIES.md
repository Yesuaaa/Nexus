## Database plan

- **API and browser persistence.** Use migrated isolated PGlite with test-owned sessions, departments, placements, policy assignments, distinct employees and relevant dates. For a merged-report case, confirm 12 in-scope merged dates/employee keys, excluded neighbor rows and distinct tie-break IDs before reading. Use no shared DB. One isolated browser server per selected fixture. The supported path is real Next document with Playwright interception → fixture relay → Express/Prisma/PGlite. Existing backend and browser checks prove sequential behavior and transaction effects. Later PostgreSQL lock tests verify independent backend processes/connection wait behavior beyond the PGlite fixture.
- **PostgreSQL preflight.** Define a dedicated opt-in URL such as PG015_POSTGRES_URL with literal loopback, explicit port, exact database `nexus_pg015_reconciliation`, unique run application_name, and a database instance/credentials owned by the task. Apply repository migrations to fresh DB without dev seed; verify identity, schema migration ledger, ReadCommitted default, connection identity, zero User, Employee, Department, sessions, audits, adjustments and workflow notifications before seeding. If any fail, record environment-blocked. Use distinct synthetic managers, one target employee, two departments, one checked assignment/workday/open suspended session and one open break, zero previous close effects.
- **Double submit.** Begin and lock the target Employee from a control connection. Start both authenticated HTTP requests and observe two distinct application backend PIDs at the expected Employee locking query, including a waiter chain if one waits behind the other. Release after observing the lock state, not after a fixed delay. Assert one 200/one 409, one persisted break/session close, one operation's audit attribution and no repeated optional workflow effects. Compare deadlock counters. Strictly bound waits and do not record bearer values.
- **Placement race.** The control connection acquires Employee lock, keeps change uncommitted, and initiates approved placement update with normal audit context. Start reconcile when initial placement is readable as old. Confirm the actual lock wait on Employee before committing the transfer. Design fixture lock order so the control writer can complete placement without waiting on a Department lock already held by the API; if a required trigger takes another lock, acquire prerequisite Department locks in production order and adapt the controlled pause point. Confirm original placement read and 409 branch rather than assuming any 409 proves race. Compare session/break, audit and notifications to the post-transfer baseline. Subsequent eligible read/write must use the committed scope. Keep this fixture separate from double submit.
- **Cleanup.** Release gates and roll back control transactions in finally, stop only test-owned Express, disconnect Prisma and observer, then drop the database provisioned for that run using authorized teardown. Never attach to shared development/production. PostgreSQL binaries, a disposable local instance, migrations, privileges and observable wait graph are environment prerequisites.

The approved source uses a read-only merged report and one explicitly authorized reconciliation mutation. No dedicated full-proxy test is planned. The two contract-dependent assertions stay deferred; the other records are ready for separately authorized Phase 2.2, with stated PostgreSQL prerequisites.
