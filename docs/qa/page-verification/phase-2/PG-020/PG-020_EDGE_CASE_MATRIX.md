The source has no Dashboard-owned upload/download, search, filter, form, or resource mutation. Those controls are not invented for this page. Malformed/unknown notification event types and missing request IDs lack a product contract; the design tests a known Client event and records the current fallback in the functional discovery report.

## Integration and concurrency boundary

The one real-path integration uses synthetic accounts, the Next.js same-origin rewrite, Express session middleware, Prisma, and disposable PGlite. It does not substitute a mocked browser response for the API. The Next rewrite is documented in `apps/web/next.config.ts:62-71`; Express mounts the request-workflow router in `apps/api/src/app.ts:85`.

PostgreSQL concurrency is **NOT JUSTIFIED** for PG-020. Dashboard state changes only notification `readAt` under authenticated recipient/resource scope. No inventory, balance, unique-allocation, or multi-record workflow invariant is concurrently mutated by this page. PGlite is sufficient for read ownership, bulk scope, and replay checks. Do not run concurrency or destructive tests during Phase 2.1.
