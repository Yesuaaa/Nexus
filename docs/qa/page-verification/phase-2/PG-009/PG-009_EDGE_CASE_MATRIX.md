## Source-supported expected failures

- Unauthenticated backend request is rejected by `requireAuth`; existing all-role API test covers 401.
- Authenticated actors without manager permission receive the backend 403 from `managementScope(..., true)`; existing API coverage includes STAFF.
- Invalid API query values are rejected by the service, but PG-009 does not construct such values. Query validation belongs to API coverage if extended; it is not a page-control case.
- When any aggregated page request fails, the async resource errors and the page suppresses collection data. Retry invokes the resource again. These are page cases A002-T003 and A010-T001.

## Boundary values deliberately not converted to product assertions

- More than 200 policies affects the “latest 200” labels and aggregate counters; C001 blocks that user-visible expectation.
- Canceled assignment counts differ between summary and per-policy relation; C002 blocks the intended per-policy display/reconciliation rule.
- API accepts `size=10` although the page uses the default `size=200`; page behavior for arbitrary size is not user-controlled and is not proposed as a PG-009 browser case.
