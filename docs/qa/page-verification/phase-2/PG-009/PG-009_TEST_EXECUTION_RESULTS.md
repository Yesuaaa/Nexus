## Initial failures and test-only corrections

### PGlite fixture

The first fixture attempts revealed repository constraints rather than product regressions: policies must have seven weekday records before assignment; archived policies reject new assignments; a canceled assignment must first be scheduled and then transitioned with `cancelledAt`; employee audit events are append-only and prevent employee deletion; active policies must be archived before permanent deletion; policy-day records must be deleted before their policy. The fixture now follows those invariants in a transaction, deletes only its assignments, policy days, and policies, and leaves the fixture employee/audit rows until the disposable PGlite test app closes. The final focused API file passed 13/13 and final combined bundle passed 45/45.

### Browser assertions

- First mocked run: four cases passed; A005-T001 failed because the locator selected only one cell rather than a column across rows. Corrected to `td:nth-child(n)` selectors.
- Next run: eight cases passed; A010-T001 failed because three loading skeleton elements matched. The assertion now checks the expected count and a visible first skeleton.
- Next run: eight cases passed; A010-T001 failed because “Policy summaries unavailable.” is rendered in two sections. Assertions now scope each error to its section.
- Next run: eight cases passed; A010-T001 failed because the recovered policy appears in both inventory and the no-history list. The recovery assertion now scopes to inventory.
- A010-T001/T002 then passed 2/2; the final complete PG-009 browser group passed 10/10. These were test-authoring locator corrections; no behavior expectation was weakened.

### Intermittent existing 820px compatibility case

The combined live route command, `pnpm --filter @nexus/web exec playwright test e2e/attendance.spec.ts --grep "grouped attendance pages use live scoped data|grouped attendance routes enforce staff and department-head boundaries" --workers=1`, exited 1 after 390px passed and the 820px instance failed at the pre-existing Check-Ins row-action `View details` assertion. The PG-009 overview comes later in that test's route loop, so PG-009 assertions were not reached in that attempt. The 1440px and boundary tests were skipped by the serial run. The same 820px test then passed in isolation; separate 390px/1440px runs and the separate boundary run passed. This reproduces the documented PG-006 T024 intermittency. It is not a PG-009 defect and remains open as a compatibility reliability risk.
