## Request, validation, authorization, and persistence boundaries

- Browser requests use the existing authenticated API client and bearer session. The checked-in web client stores access/refresh tokens in sessionStorage (apps/web/src/features/auth/api/auth-api.ts). This inventory does not treat local UI eligibility as API authorization.
- Express router mounts are verified in apps/api/src/app.ts. Feature controllers and services apply operation-specific validation and authorization; see the authorization matrix for route-level scope.
- Database model names above are the models established by page feature and API domain source. A model listed for a domain is not a claim that every page operation reads/writes every listed model.
- The strongest static chain is route → imported feature page/API client → mounted Express router → domain/schema. Any endpoint hidden behind a generic async hook, dynamic module, or feature callback and not resolved above remains PARTIALLY VERIFIED or UNVERIFIED.
- No live database, migration state, file storage, realtime transport, payment provider, or API response was inspected.
