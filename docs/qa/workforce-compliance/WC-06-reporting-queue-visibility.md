### WC-06-F01 · Requests Overview displays stale leave counts across scopes

**Before the fix.** As Alpha Head, open Requests Overview with the WC-06-C06 fixtures. The department view shows four leave requests, two submitted. Hold only the personal leave overview response and select **My requests**. The real adjustment summary returns `200` with zero groups. The browser meanwhile shows `Pending 2`, `Approved 1`, `Request status 4 total` and `2 awaiting`, all from the preceding department leave response. Release the real personal leave response (`200`, empty groups). The counts settle to zero.

**Before the fix after denial or failure.** With the department view loaded, hold the personal leave request while switching to **My requests**. As HR, remove the Alpha Head (`PUT /api/departments/:id`, `200`). In the existing Head tab switch back to **Department requests** while the personal request is still held. Both team overview endpoints return real `403`s. The Leave panel still displays `4 total` alongside its unavailable message. In a separate injected `503` on the team leave endpoint, the combined Request status rendered the one successful adjustment as `1 total` and `100% Verified` while the all-domain figures showed unavailable. The server-side authorization checks rejected the former reviewer's fresh reads, and the remaining count came from the same browser's earlier authorized response.

**Root cause.** The shared async resource keeps its last successful value across request keys and errors. Requests Overview masked the previous adjustment response during loading, while it still used the retained Leave response for combined figures, status shares, and attention. Requests Overview also checked readiness only against the adjustment endpoint in those sections. [Overview composition](../../../apps/web/src/features/attendance/pages/attendance-requests-overview-page.tsx) · [Async resource state](../../../apps/web/src/lib/use-async-resource.ts)

**Implemented fix.** The summaries remount when the selected scope or account authority key changes. Each mount starts fresh reads and uses the existing resource cleanup to abort and ignore responses from the previous mount. Each source exposes its counts after the current request succeeds. Combined figures, shares, and attention totals wait for both successes. A temporary failure keeps the successful current-scope section visible and Retry reloads the failing source. A `401` or `403` on either endpoint hides all figures for that scope, and Retry rechecks both endpoints. [Implementation](../../../apps/web/src/features/attendance/pages/attendance-requests-overview-page.tsx) · [Updated Requests Overview contract](../../features/attendance-interface.md#grouped-workspace-pages-2026-11-14)

**Changed files.** `attendance-requests-overview-page.tsx` contains the scoped rendering change. `attendance.spec.ts` adds regressions using the existing Playwright fixture. `attendance-interface.md` documents response handling for Requests Overview. **Root cause and implementation.** The summary included suspended sessions in its total but omitted them from the breakdown. The CSV used `endedAt ?? "Open"` for every unfinished session. ### WC-06-F03 · Request status shares omit terminal leave and repeat identical leave statuses

**Before the fix.** The baseline browser run reproduced WC-06-C06 with both summary endpoints returning `200`. Request status showed `5 total`, while the rows counted Pending 2, Verified 1, Approved 1, and Rejected 0. Their shares were 40%, 20%, 20%, and 0%. Cancelled appeared only in the Leave section. The Leave section listed `Submitted 1` twice, and Needs attention listed `Leave 1 pending` twice because the two requests had different categories. Reversed was also missing from the combined status list.

**Root cause and implementation.** The denominator included every Leave status, while the table iterated only the adjustment statuses. Separate Leave category rows discarded their category labels, and those rows produced identical type-and-stage keys in Needs attention. The page now aggregates Leave counts by status and uses a single combined count per displayed status for the status table, total, and shares. It retains the existing Submitted-to-Pending mapping in the combined report and adds separate Cancelled and Reversed rows. Leave retains its own status labels. Needs attention uses one row per request type and review stage. The page still requires both sources to succeed in the current scope before displaying any combined figures.
