# Workforce Compliance Integration QA · Phase 3

**November 22, 2026 · Cross-module workflows and authorization · WC-I3-F01 and WC-I3-F02 Verified**

The initial audit reproduced two defects on PostgreSQL 16.15. Reconciliation could record a clock-out one hour early during a repeated local time, and employee transfers could move actionable Leave requests to a receiving Department Head's queue without delivering a notice. Focused Chromium and PostgreSQL retests verified both fixes. The tested attendance, correction, overtime, Leave approval and reversal, and account deactivation journeys otherwise committed their expected records and history.

### WC-I3-F02 · High · Verified · Reconciliation silently chose the earlier offset

#### Original reproduction and root cause

1. In a disposable fixture, assign a policy to a Staff employee, clock in at `2026-11-01T08:10:00Z`, and disable the Staff login with the session open.
2. Sign in as HR in a browser set to `America/Los_Angeles`. Open the suspended session in **Time Logs → Records → View details → Reconcile shift**.
3. Enter November 1 at 01:30 as the confirmed clock-out for the second occurrence of that local time. Supply a note and submit.

The old form passed the bare `datetime-local` value to `new Date(end)`. Chromium interpreted it in the device timezone and silently chose the earlier PDT occurrence. A fresh baseline run against PostgreSQL 16.15 reproduced the original outcome. The browser posted `2026-11-01T08:30:00.000Z` with a note identifying the second occurrence. Express returned `200`, PostgreSQL stored the posted instant, and Time Logs reported **20 worked minutes**. The intended `2026-11-01T09:30:00.000Z` yields **80 worked minutes**. The reconciliation API already validates and stores the supplied instant. [API timestamp validation](../../../apps/api/src/features/attendance/attendance.validation.ts) · [Reconciliation service](../../../apps/api/src/features/attendance/attendance.service.ts) · [WC-04-F02](WC-04-attendance-corrections.md)

#### Fix and changed files

- The shared Attendance date/time input extracts the correction form's `DateInput`, UTC-offset `FilterSelect`, occurrence resolver, and validation messages. It uses the existing `deviceDateTimeOccurrences` and `deviceDateTime` utilities. The correction dialog keeps its ordering validation and preserves the recorded offset and seconds of untouched prefills. ### WC-I3-F01 · Medium · Verified · Employee transfer left actionable Leave without a notice

#### Original reproduction and root cause

1. In a disposable fixture with independent source and destination Heads, submit two staff Leave requests on distinct dates. Verify one with the source Head.
2. Transfer the employee through Employee Directory placement. Inspect the receiving Head's team queue, request details, and notification inbox.
3. Compare the authorized queue and inbox responses with persisted notifications and the LeaveDecision history. Attempt final approval as HR before and after receiving-Head re-verification.

The initial audit and a fresh PostgreSQL 16.15 baseline both found the request in the receiving Head's team queue and detail at `SUBMITTED` version 1 or `VERIFIED` version 2. Both details allowed verification. Neither request had a receiving-Head inbox or database row. Reads already used the employee's current department, while the Leave notice writer ran on submission and Head eligibility changes. Ordinary employee placement updated the employee and linked account without calling that writer. The Phase 2 migration covered missing historical `SUBMITTED` notices at migration time.
