[API startup](../../../apps/api/src/server.ts) · [Production Compose](../../../compose.prod.yaml)

`/api/health` checks process liveness. `/api/db-check` checks connectivity. `/api/ready` confirms a writable connection to the `public` schema, the exact active release ledger by migration name and SQL checksum, and the Prisma model tables, scalar columns and enum labels. It rejects unresolved attempts and unexpected active entries. An explicitly rolled-back attempt may remain in history after a successful rerun. Probes use a bounded transaction, a 2.5-second PostgreSQL statement deadline and the existing pool. Concurrent requests share an in-flight probe and the next request checks fresh state. During shutdown or a failed probe, production application handlers return the same generic `503` as readiness. Production maintenance jobs also wait for a compatible schema. [Health routes and request guard](../../../apps/api/src/features/health/health.controller.ts) · [Schema probe](../../../apps/api/src/features/health/schema-readiness.ts) · [Express wiring](../../../apps/api/src/app.ts) · [Database adapter](../../../apps/api/src/lib/db.ts) · [API startup](../../../apps/api/src/server.ts)

The job compares the runtime and migration connections against the same writable database, runs `prisma migrate deploy` with Prisma's advisory lock, then verifies the resulting ledger and schema through `DATABASE_URL`. `DIRECT_URL` can point to a different connection endpoint for the same database. API replicas wait for job exit `0` and web waits for API health. The migration image includes Prisma CLI. The API runtime image carries the release's migration files for checksum verification. The supported release procedure pauses ingress and stops older API replicas during migrations. ### Confirmed causes

1. **Attendance Overview occupied the Node event loop inside an interactive read transaction.** A full-range request loaded 4,827 workday keys and hydrated 4,827 workdays and sessions, plus policy, adjustment, break and employee relations. Each conversion validated its timezone by constructing a formatter and then constructed another formatter to render the local date. Five single-client allocation traces each counted 19,308 formatter constructions taking 1.00–1.85 seconds of a 1.41–2.34 second business transaction. Each short-range trace counted 748 constructions. ## WC-I4-F02 Remediation 4

### Driver checkout classification

The waiting queue in `pg-pool` 3.14.0 emits a plain `Error` with the exact message `timeout exceeded when trying to connect` after the configured 5,000 ms checkout deadline. ## Unverified requirements and scope limits

- **Production environment.** TLS and trusted proxy configuration, provider pooler and failover behavior, production DB grants, effective secret policies, image security scan and deployed CI, monitoring and traffic-withdrawal infrastructure.
- **Recovery and capacity.** Mixed-version app/database compatibility and rollback, production-sized migration and restore, recovery after database-host loss, crossed administrative deadlocks, sustained load, and agreed capacity and recovery objectives.
- **Browser.** Full approval and transfer workflows across browser engines and devices, and error recovery outside the tested login, Workforce Logs and Check-Ins screens. The Phase 4 validation used Chromium and the production web/API.
- **Outside the current contract.** Full-history CSV export, partial-day Leave, accruals, payroll, automated coverage replacement and confirmed availability slots. Workflow notifications are in-app records. [Leave contract](../../features/leave-requests-plan.md) · [Workforce Logs contract](../../features/workforce-compliance-logs.md)

## Final deployment recommendation

**Hold production.** Allow a controlled pilot after WC-I4-F02 and F03 are resolved and the target ingress, database grants and log handling are verified. Use one serving replica or verified affinity for Workforce Logs. Demonstrate migration and interrupted rollout recovery, a backup and restore under agreed recovery objectives, and safe traffic withdrawal in a target-like environment. Assign owners and exercise alerts for health, migrations, request failures, review backlogs, missing notices, suspended shifts and audit attribution. Establish pilot capacity and abort criteria from a representative workload, then repeat the core production journeys against the exact release artifact.
