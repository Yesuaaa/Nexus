# Phase 5.1 — Feature and regression coverage assessment

## Scope and evidence

This is a source-based assessment of the 18 official routes. It reuses the [Phase 2 route coverage matrix](../../migrations/phase4/baseline/artifacts/coverage-matrix.md), [preserved baseline report](../../migrations/phase4/baseline/artifacts/report.md), and [Phase 4 verification record](../../migrations/phase4/verification.md). Original `PW-###` identities below are the non-exclusive route memberships recorded in Phase 2; the preserved Phase 4 mapping keeps those identities attached to the migrated specs. This document does not recreate the test inventory.

Phase 4 preserved 35 specs, 157 declarations, 292 expanded identities, 1,630 assertion sites, and 4,211 preservation mappings. Its final recorded Playwright run was **287 passed, 0 failed, 5 skipped**. `PW-124`–`PW-128` are opt-in live-backend cases and were skipped.

### Coverage labels and execution boundary

| Label | Meaning in this assessment |
| --- | --- |
| **COVERED** | The implemented behavior is directly asserted in the named regression layer. |
| **PARTIALLY COVERED** | Relevant scenarios exist, but a notable implemented behavior or boundary is absent. |
| **NOT COVERED** | No relevant Playwright scenario was found for the implemented behavior. |
| **BLOCKED** | The application does not define the success contract needed for a meaningful test. |
| **INTENTIONALLY UNSUPPORTED** | Product documentation or current behavior excludes the capability. |
| **UNVERIFIED** | Source or test code exists, but the evidence does not establish execution against the real API/backend. |

Phase 4 browser cases primarily use `page.route` mocks for `/api/*`; they validate browser behavior and mocked request/response handling, not persistence or server authorization. The local SSE stub in the messaging suite checks browser transport only. Separate Express/PGlite tests exist in `apps/api/src`, including auth, account policy, client/employee integration, inbox, request workflow, conversations, profile, settings, and system-regression suites. They are not Playwright identities, and the preserved Phase 2 report says those API tests were not run for its browser baseline. No API suite or live service was run for Phase 5.1. Therefore API test-file presence is not reported as backend execution evidence.

## Uncertainty and completion decision

- The Phase 2 execution used an existing build whose source revision was recorded as unverified; the Phase 4 final execution reconciled all preserved identities but did not run a backend or production database. This assessment makes no claim of source-to-build equivalence or real persistence.
- Mocked role fixtures prove UI behavior for supplied roles/permissions. Server authorization remains a separate API-layer concern; API test files are present, but their execution is not evidenced by the Phase 2/4 Playwright baseline.
- Phase 4 records Chromium browser coverage only. Screenshots are artifacts, not visual snapshot assertions; Firefox/WebKit and touch-device execution are not part of the baseline.
- **Phase 5.1 is complete:** all 18 pages have current implementation summaries, original PW identity attribution, coverage-layer boundaries, and material gaps/limitations. No application, existing test, assertion, configuration, Phase 2, or Phase 4 evidence was modified. Stop here; Phase 5.2 and Phase 6 are not started.
