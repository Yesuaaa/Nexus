# System Logs UI/UX refinement (Phase 3D)

Developed: 2026-11-16

Follow-up: [Phase 4A Workforce Compliance audit integration](system-logs-attendance-audit.md) adds limited Attendance metadata to the existing audit view and source coverage. The UI-only source/coverage statements below describe the Phase 3D handoff.

**UI-only refinement. Production System Logs remains disabled.** The three existing views remain Activity & Audit, Errors & Exceptions and System Health. APIs, schemas, history readers, logging collectors, health probes/status calculations, authentication, activation guards and business logic are unchanged. This follows [Phase 3C](system-logs-system-health.md) and preserves earlier uncommitted work.

## Simplified default interface

Activity & Audit continues to initialize its applied filters automatically from the retained originating workspace, using the existing `initialHistoryFilters` and workspace provider. That behavior was reused rather than replaced by an effect that could overwrite manual choices. The current **applied** module is now a small contextual `Pill`; there is no module form field or Advanced Filters section in the default interface.

The main form contains just the existing from/to UTC dates and optional **Event search**. The dates share a row on mobile, and search spans the row; larger screens place all three controls together. Event search uses the existing **exact approved event-name** filter, not new free-text/full-text search. The placeholder makes that limit explicit. Apply retains the existing validation, cursor reset, result replacement and detail-close behavior.

A discreet **All Modules** action immediately broadens a supported workspace scope without discarding the current dates, search, specialized filters or pending edits to other fields. **Workspace only** returns to the retained originating workspace without modifying the shell's workspace context. These actions replace the ordinary module field; All Modules still means the two integrated histories, not complete application-wide coverage. Reset clears dates/search/specialized filters to their existing defaults while preserving the current module scope, so resetting the form does not silently broaden a workspace investigation.

Specialized capabilities remain available through a small **Filter options** action using the existing SidePanel kit. Its investigation panel retains module override, source, action, actor/subject IDs, subject type and operation UUID. The main form does not display those fields. Applied-option counts and pending specialist edits are indicated outside the panel. Closing or pressing Escape preserves unapplied draft edits; Apply validates and applies the same existing query contract, then closes the panel. No new filter, endpoint or persisted preference is introduced. Operation investigation and Back retain their existing filters and cursor snapshot; hidden specialist fields do not disappear from requests.

## Disclosure, empty states and readability

- The always-visible production notice is now a compact **Offline only / Unavailable for production release** summary. Native keyboard-accessible `<details>/<summary>`, already used elsewhere in Converyn, expands the original release prerequisites and supported-source limitations. Expanding it does not change any activation state or make a request.
- Supported-module coverage explanations use the same disclosure pattern. The scoped coverage label and 31-day UTC query bound remain visible. Pending module changes still explain that Apply is required; the contextual module label always describes the applied scope.
- An unsupported applied module now has **one** `EmptyState` inside the existing table, explaining the unavailable integration and offering **Show All Modules**. The duplicate coverage box, irrelevant table headings and disabled pagination are omitted in that state. The contextual action preserves other filters. It never claims that no activity occurred.
- Empty filtered management results and empty/expired error-buffer results reuse `EmptyState` with the existing honest coverage language. Loading, errors, incomplete pages, omission/source warnings and retry behavior remain distinct.
- Event/operation page counts and returned-error counts use readable existing pills, singular/plural labels, and clear retained/page scope. Snapshot time stays alongside the summary. No global total or reconstructed expired history is invented.
- Error rows now match the audit table's compact typography, row separators and module/category hierarchy. The empty error row uses the existing table-cell structure with its column span.
- System Health retains `KpiCards`, all status strings, observation times and instance-local limitations. Icons use the existing semantic status colors, and a concise **Status key** replaces the repetitive per-component badge list. Healthy, Degraded, Unavailable and Unknown each have text and an explanation, so color is supplementary. No health status is recalculated in the UI.

## Remaining usability limits

Event search requires an exact approved event name; autocomplete and arbitrary text search are not added. Specialist investigations require opening Filter options by design. Unsupported workspaces still have no integrated management source; broadening to All Modules does not create coverage. Errors and Health remain instance-local, non-durable and subject to the existing expiry/capacity/loss limits. Browser snapshots do not continuously update; existing refresh behavior remains unchanged. Production prerequisites, including durable access evidence, remain unresolved as documented in earlier phases.

**Stop after Phase 3D.** No additional logging feature, infrastructure or production activation is included.
