# Settings implementation plan

Goal: Deliver the approved three-tab web Settings page beneath Profile in the account menu, on branch 160. Existing My Profile owns personal details and Account Management owns other users.

Architecture: Extend existing authenticated auth routes and session records. Store per-user preferences, expose only implemented notification channels, and use existing password-change handling. No commits or live database migration execution.

Tasks:

- [x] Backend: validated user preferences, owned session listing/revocation, user-agent and last-active capture, notification preference enforcement; migration and generated client; PGlite regression coverage.
- [x] Frontend: Settings navigation and responsive three-tab page, password control, session management, persisted notifications and display preferences, actual formatting integration.
- [x] Integration: review ownership/validation and empty/error states, run meaningful feature checks, format/lint/typecheck.

Review focus: cross-account session IDs must never revoke another user; timezone and format inputs must be allowlisted; old sessions without metadata must display honestly; preferences must not leak between accounts; critical security behavior must remain active.

Implementation uses the subagent-driven-development skill for separate backend and frontend units, followed by integration review. The user approved this feature through the GitHub issue draft and explicitly authorized implementation. Work remains uncommitted.
