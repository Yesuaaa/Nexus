**Page:** `/register`  
**Audit date:** 2026-11-06

## Input inventory and rules

| Surface               | Behavior and validation                                                                                                                                                                                                                                                                                             | Coverage and scope                                                                                                                                                                                               |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Full name             | Required, trimmed and NFC-normalized, 2–100 characters. Accepts Unicode letters and combining marks, spaces, periods, hyphens, and apostrophes.                                                                                                                                                                     | Tests cover empty/whitespace, short/long boundaries, invalid symbols/digits, international names, and malformed runtime values.                                                                                  |
| Contact number        | Required Philippine mobile number: exactly 11 ASCII digits beginning with `08` or `09`. Invalid characters remain visible and are rejected instead of being silently removed. Surrounding whitespace is trimmed.                                                                                                    | Tests cover empty/whitespace, wrong prefixes, short/long values, spaces, letters, and `+63` formatting.                                                                                                          |
| Email                 | Required, maximum 254 characters; local part maximum 64 and canonical domain maximum 253. The local part must contain at least one letter or number. Registration requires a valid address ending in `.com` or `.ph`. Unicode local parts and IDN domains are accepted; the API canonicalizes domains to IDNA form. | Tests cover whitespace, punctuation-only local parts, malformed/dotted addresses, unsupported suffixes, domain boundaries, plus tags, Unicode, and canonicalization. General Login suffix rules remain separate. |
| Password              | Required, at least 12 characters and at most 1024 UTF-8 bytes. Requires Unicode uppercase and lowercase letters, a decimal digit, and a symbol or whitespace character. The exact value is preserved; it is not trimmed.                                                                                            | Tests cover missing/whitespace, minimum and maximum boundaries, multibyte byte limits, missing character classes, and international characters.                                                                  |
| Password confirmation | Required and must exactly match the password. It is client-only and is not included in the API request.                                                                                                                                                                                                             | Tests cover empty, whitespace, mismatch, and match cases.                                                                                                                                                        |
| Language selector     | English or Filipino; changes page copy and is not sent in the registration request.                                                                                                                                                                                                                                 | Unit coverage checks English/Filipino validation messages. Browser interaction could not be rerun here.                                                                                                          |
| Registration request  | `POST /api/auth/register`, JSON body with `fullName`, `contactNumber`, `email`, and `password`. Query parameters and extra privilege fields are ignored; the API creates the account as `USER`.                                                                                                                     | PGlite tests send null/array/wrong-type/malformed payloads and forged role/status properties. Added browser cases assert the JSON body and headers, but Playwright could not run here.                           |

No optional registration inputs, file uploads, dates, numeric quantities, dropdowns, hidden fields, or editable tables are present. The `role` and `email` query parameters do not prefill fields or alter account privileges.

## Required fields, types, and boundaries

- All five form fields are required. Whitespace-only name, contact, email, and password values fail validation; password confirmation must be present and match exactly.
- API validation safely rejects missing, null, scalar, array, and object values. The API does not trust client-side validation and always assigns the `USER` role.
- Email supports the required `.com` and `.ph` suffixes, common address punctuation, internationalized local parts containing at least one letter or number, and IDN domains. The API stores the canonical IDNA domain form, which is also used during login.
- Password length and composition rules are enforced by both client and API. Byte length uses UTF-8, so multibyte input is checked against the 1024-byte limit.
- There are no date, time, quantity, boolean, enum, file, rich-text, search, filtering, pagination, or bulk-edit inputs on this page.

## Issues found and fixes

|   # | Issue                                                                                                                                 | Fix                                                                                                         | Verification                                                                   |
| --: | ------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
|   1 | API name validation checked only length and accepted characters the UI rejected.                                                      | Apply the same Unicode-aware name rule on the API.                                                          | API schema and registration tests.                                             |
|   2 | API contact validation accepted formatted numbers and values outside the required `08`/`09` 11-digit format.                          | Enforce the platform's exact Philippine mobile format server-side.                                          | API schema and tampered-request tests.                                         |
|   3 | API registration accepted generic email formats, including unsupported suffixes and malformed dot/domain labels.                      | Add registration-specific `.com`/`.ph` format and length validation.                                        | API schema and PGlite registration tests.                                      |
|   4 | API password validation enforced length and bytes but omitted uppercase, lowercase, digit, and special-character rules.               | Enforce the same composition rules server-side.                                                             | API auth and PGlite registration tests.                                        |
|   5 | The phone input silently stripped non-digits, changing pasted or typed input before validation.                                       | Preserve the entered value and show a validation error for invalid characters.                              | Added Playwright case; browser execution is blocked here.                      |
|   6 | The client validator assumed values were strings and could throw on null, missing, array, or object values.                           | Type-check values before trimming or validating them.                                                       | Web validation unit tests.                                                     |
|   7 | ASCII-only password classes rejected valid international uppercase/lowercase letters and decimal digits.                              | Use Unicode character classes on both client and API; combining marks alone do not satisfy the symbol rule. | Web and API auth tests include accented letters and non-ASCII decimal digits.  |
|   8 | Registration email validation rejected internationalized addresses and did not canonicalize IDN domains consistently for later login. | Accept internationalized input and store/use its canonical IDNA domain form.                                | API registration and login PGlite tests; web validation unit test.             |
|   9 | The local email part could consist only of punctuation, so an address such as `---@email.com` passed validation.                      | Require at least one Unicode letter or number in the local part on both client and API.                     | Web validation and API registration tests reject punctuation-only local parts. |

## Verification

- Web auth validation tests: 8 passed, including registration boundary, Unicode, and malformed-value cases.
- API auth schema tests: 4 passed.
- PGlite JWT/session suite: 11 passed, including invalid and internationalized registrations, forged role/status fields, and login.
- Client integration suite: 10 passed; password management test: 1 passed.
- New Playwright tests cover required whitespace, invalid phone input preservation, punctuation-only email local parts, Unicode registration payloads, URL query tampering, request headers, and rapid duplicate submits. They are in `regression.spec.ts`, which is included by the standard `**/*.spec.ts` matcher. The root `pnpm test:e2e` runner forwards `--ui`, so `pnpm test:e2e -- --ui` includes these cases in Playwright UI mode. A direct `playwright test --list --grep registration` check discovered the cases. They are typechecked but were not executed because the sandbox denied spawning Playwright's worker.
